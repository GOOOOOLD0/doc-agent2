# 语义层加工提示词模板(semantic_enrichment_prompt)

## 何时用这个模板

`raw_chunks/<article_id>.structured.json`(由 `clean_ocr_text.py` 按款号
重排后产出)生成后,用本模板对每一款调用 LLM,一次性产出:
1. 全条摘要/关键词/相关条款候选(原有功能);
2. **逐款的异常符号/错字清洗结果**(新增功能,取代了旧版写死的
   `ocr_correction_dictionary.json` 字典匹配)。

## 为什么把错字清洗也交给 LLM,而不是继续用字典

字典只能覆盖"见过的"错误模式,换一份文档、换一个 OCR 引擎,错误
模式完全不同,字典需要无限维护下去。而"这个字符在这个上下文里
是不是识别错了"本质上要靠语义判断——这正是 LLM 擅长、规则脚本
做不到的事。所以这里把职责边界改成:

- **结构性操作(换行、分段、页码剥离)** —— 规则脚本做(`clean_ocr_text.py`),
  确定性强,不需要语义判断;
- **字符/符号级的异常判断(是不是错字、是不是无意义乱码)** —— 交给 LLM,
  因为这需要理解上下文才能判断。

**红线不变**:LLM 只能"清洗明显的识别噪声"(错别字、多余符号、
不完整的乱码片段),不能改写用词、不能替换成"读起来更通顺"的
表达、不能删减或增补实质内容。每一处改动都必须记录原文/改动后
文字/改动理由三元组,方便人工逐条核实,而不是让 LLM 悄悄改完就算。

## 提示词模板

```
你正在处理《无线电规则》(2020年版)第<article_id>条,原文已经按款号
拆分为结构化 JSON(见下方"款级原文")。请对每一款执行两项任务:

任务A:异常符号/错字清洗(逐款进行)
- 只处理明显的 OCR 识别噪声:形近字错误(如"笫"应为"第"、"肘"在
  法律文本语境下应为"时")、字母丢失或错位(如"IU-R"应为"ITU-R"、
  "[U-R"应为"ITU-R")、残留的孤立符号或水印字符、多余的半角/全角
  混排空格;
- 不允许:改写句式、替换同义词、调整语序、删除或添加实质性内容,
  哪怕原文读起来有点绕口也不要"优化表达";
- 拿不准是不是错字时,不要擅自处理,原样保留并在 changes 里如实
  说明"存疑,未处理";
- 每一处实际改动,都要在 changes 里记录 {"from": 原文片段,
  "to": 改动后片段, "reason": 判断依据};没有需要改的款,changes
  给空数组,不要为了"看起来有产出"硬找问题。

任务B:全条摘要与引用抽取(和之前一致)
- 用一到三句话概括本条内容,不得添加原文没有的信息;
- 提取3-8个关键词;
- 找出原文中出现的所有条款引用(如"见第9条""见5.150""见附录1"),
  原样列出引用文字,不做定位判断(定位由规则脚本处理);
  **必须是原文里逐字能找到的文字,生成的每一条都会被脚本拿去原文
  里做子串匹配核对,匹配不到会被标记为"疑似幻觉"并展示给人工核查,
  所以宁可少列,不要多列。**
- 摘要基于清洗后的文字理解,但清洗前后的原文都必须原样保留在输出
  里,不能只留清洗后的版本。

请以如下 JSON 格式输出,不要输出其他内容:

{
  "summary": "……",
  "keywords": ["……", "……"],
  "raw_cross_references": ["见第9条", "见5.150"],
  "notes": ["整条层面的备注,如清洗覆盖率、明显仍有疑问的地方"],
  "clauses": [
    {
      "clause_id": "3.2",
      "cleaned_text": "……清洗后的本款文字,原文没有明显错误时与原文一致……",
      "changes": [
        {"from": "笫", "to": "第", "reason": "OCR形近字错误,上下文为条款标题引用"},
        {"from": "[U-R", "to": "ITU-R", "reason": "字母缺失/误识别,上下文明确指国际电联建议书"}
      ]
    }
  ]
}

款级原文(structured.json 的 clauses 数组)如下:
<粘贴 raw_chunks/<article_id>.structured.json 里的 clauses 数组>
```

## 复杂版式页面(表格、旋转页眉)的处理

如果某条跨越的页面本身版式复杂(大表格、旋转页眉、多栏交错),
`clean_ocr_text.py` 重排后的文字可能仍然破碎、无法可靠对应到某一款。
这种情况不要勉强套用上面的模板硬清洗,而是把该页原图直接交给具备
视觉能力的 LLM 做转录,提示词如下,转录结果替代该款原来的 OCR 文字
作为 `raw_chunks` 的输入,再重新走一遍任务A/任务B:

```
以下是《无线电规则》(2020年版)第<article_id>条原文的页面图片
(第<page>页)。请逐字转录页面上的正文(忽略页眉页码等版式元素,
按阅读顺序还原文字,遇到旋转文字按其自然阅读方向转录,表格内容
按行列结构转录,不要跳过任何段落)。不要在转录阶段替换成"看起来
更通顺"的文字,宁可标记不确定,也不要用自己的理解替代实际看到的
文字。输出:{"transcription": "……", "transcription_confidence": "高/中/低"}
```

## 后续处理

`generate_wiki_pages.py` 读取 `semantic/<article_id>.json`,把
`clauses` 里每一款的原文(来自 structured.json)和 `cleaned_text`
并排组装成表格,放进正式页面的"原文正文"区块(见
`article_page_template.md`);`changes` 汇总进"备注/待确认项";
`raw_cross_references` 交给 `cross_reference_rules.md` 的规则脚本
做接地检查和目标定位,不由 LLM 直接产出最终链接。
